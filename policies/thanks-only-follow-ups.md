# Thanks-Only Follow-Ups

# Summary

When a customer's latest message is thanking us for content recommendations we just sent — calling them a starting point, saying they help, or referring to "these"/"this" (the recs) — and the message contains no new request, that is a thanks-only follow-up. Close with no reply. Do not lift a phrase or context from the original request out of the thanks message and treat it as a new ticket. If a thanks-only close has already landed, reread the thread carefully before undoing it.

# Trigger Conditions

- **Ticket signals:** customer's latest message follows our content recommendations; customer says "thank you," "I appreciate your help," "this is helpful," "great starting point," or similar gratitude; customer refers to "these," "this," or "the recommendations" in a way that points back to what we just sent
- **Account signals:** none required
- **Keywords / phrases:** "thank you," "thanks," "appreciate," "helpful," "great start," "starting point," "these," "this," combined with no new question or request

# Required Context

- [ ] Did we just send content recommendations in the previous message?
- [ ] Is the customer's latest message thanking us for those specific recommendations?
- [ ] Does the latest message contain any new request, or does it only express gratitude?
- [ ] If there's context from earlier in the thread (e.g., why they originally asked), is that context being raised again as a new request, or is it simply background for the thanks?

# Policy / Correct Response

## Standard Case

**Close with no reply.** If the customer's latest message is thanking us for recommendations we sent and contains no new request, the conversation is resolved. Do not reopen to send a second batch of unrelated recommendations. Do not treat context or background from earlier in the thread as a new ticket just because it appears in the thanks message.

**Quote the customer's latest message before deciding.** When evaluating whether a message is thanks-only, read and quote the latest customer message to confirm it contains no new request. If you've already closed the conversation and a teammate or system asks you to reconsider, reread the thread before undoing the close.

## Variations

- **Thanks with no elaboration:** "Thank you!" or "I appreciate your help." — Close with no reply.
- **Thanks that refers to the recommendations:** "This is a great starting point and I appreciate your help." — Close with no reply.
- **Thanks that includes original context but no new ask:** E.g., customer thanks us for death/impermanence recommendations, and the message includes "I need the right session for my subjects" (the reason they originally asked) but no new request — this is background for the thanks, not a new ticket. Close with no reply.

## Edge Cases & Exceptions

- **Message contains thanks AND a new question:** Not thanks-only. Reply under the relevant policy and address the new request.
- **Customer reopens after a thanks-only close:** Treat the reopened message as a fresh request under the relevant policy. The thanks-only close was correct; the new message is now the active request.

# Action Classification

## No Action Required (close only)

Standard thanks-only follow-ups: close with no reply.

## Human Action Required

None for standard thanks-only cases. The close is the only action.

## Do Not Auto-Send Conditions

- Not applicable — no draft is sent for thanks-only closes. The conversation is closed directly.

## Escalation Triggers

- None — this is a straightforward close decision.

# Confidence Notes

- **High confidence areas:** Recognizing simple "thank you" messages with no follow-up question. Distinguishing original context (background) from a new request.
- **Judgment call areas:** When a thanks message includes elaboration or context that could be interpreted as a new ask.
- **Gaps:** No saved reply exists for this scenario because no reply is sent. This policy governs the close decision only.

# Saved Reply Mapping

No saved reply applies — thanks-only follow-ups are closed with no reply.
